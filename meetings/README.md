# meetings — 議事録・進捗管理

ミーティングの記録と進捗管理ドキュメントを置く場所。

> **議事録に個人情報を書かない。** このリポジトリは public 前提で運用する。
> 出席者は「A・B・C」やイニシャルにするか、氏名を書く必要があるなら
> **議事録そのものを private リポジトリ側に置く**。
> 線引きは [`../docs/before_coding.md`](../docs/before_coding.md) を参照。

## 構成

| ファイル | 内容 |
|---|---|
| `_template.md` | 議事録テンプレート（コピーして使う） |
| `wbs.md` | **WBS（作業分解表）**。最初に埋める |
| `gantt.md` | ガントチャート（Mermaid） |
| `2026-04-15_kickoff.md` | 議事録の記入サンプル（実物ができたら削除してよい） |

## 議事録の作り方

### 方法A: 1 ファイル 1 回（回数が少ない・資料が少ない場合）

1. `_template.md` をコピーして `YYYY-MM-DD_<topic>.md` にリネーム
2. ミーティング中に議題・決定事項・Action Items を埋める
3. 完了したらコミットして push

### 方法B: 1 フォルダ 1 回（推奨・資料が増える場合）

回を重ねると、議事録だけでなく**その回の配布資料・ホワイトボード写真・
検討メモ**が溜まる。ファイルが増えてくるとフォルダに分けたほうが探しやすい。

```
meetings/
├── 0415_1回/
│   ├── 議事録.md
│   └── 検討メモ.md
├── 0422_2回/
│   ├── 議事録.md
│   └── wbs_割り当て.md
└── 0429_3回/
    └── 議事録.md
```

**どちらでもよい。** チームで決めて、途中で変えないことのほうが大事。
（途中で変えると「あの資料どこ？」が発生する）

## 進捗管理のコツ

- **WBS** は最初のうちに作る。粒度は「1 タスク = 数時間〜3 日」が目安
- **WBS の 1 行を GitHub Issue 1 件にする**と、進捗が GitHub 側でも追える
  （手順は [CONTRIBUTING.md](../CONTRIBUTING.md#8-issue-で作業を管理する)）
- **ガントチャート** は WBS と連動させる。Mermaid は GitHub で自動描画される
- 毎週のミーティングで進捗確認し、WBS の「状態」列を更新する
- **決定事項は必ず書く。** 「なんとなく決まった」は 2 週間後に必ず揉める

## 議事録に必ず残す 3 つ

| 項目 | なぜ |
|---|---|
| **決定事項** | あとで「そんな話だっけ」を防ぐ |
| **Action Items（誰がいつまでに何を）** | 担当が決まらないタスクは進まない |
| **持ち越した論点** | 次回の議題がそのまま作れる |

議論の経過を全部書く必要はない。**上の 3 つだけは絶対に書く。**

## 不要な班は

進捗管理を別のツール（Notion, Trello, GitHub Projects 等）で行うなら、
このディレクトリごと削除してよい。ただし **WBS だけはどこかに必ず作る**
ことを勧める（「何が終わっていないか」が見えないまま終盤に入るのがいちばん危ない）。
