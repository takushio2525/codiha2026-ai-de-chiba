## 🚫 絶対に守るルール

### 1. ファイル名に日本語を使わない

**この配下のファイル名・ディレクトリ名はすべて英数字**（`_` `-` は可）にする。
提出要件で明確に禁止されている。

リポジトリ直下の `課題/` は zip に含めないので日本語名のままでよい。
**この線引きを崩さない**（提出対象を `app/` の外に置かない・`app/` の中に日本語名を作らない）。

### 2. `docker compose up` で動くこと

審査員は Docker で動作確認する。**コードは
「必要な機能に対して実装した割合 × 正しく動作する割合」の掛け算**で採点されるので、
**動かない機能を積むより、動く機能を確実に仕上げるほうが点になる。**

- ベースイメージは可能な限り **Docker 公式イメージ（DOI）**、タグを固定する（`latest` を使わない）
- 審査員の環境に無いもの（外部 API のキー、手元のデータファイル）が無いと動かない構成にしない

### 3. 氏名・所属を含む `readme.txt` はコミットしない

**このリポジトリは public。** `readme.txt` には提出者の氏名と所属を書く必要があるが、
それを public リポジトリの履歴に入れてはいけない。

**`app/readme.txt` は `.gitignore` 済み。** 提出直前に手元で作り、zip に入れて提出する。

## 置くもの

| ファイル | 必須 | 内容 |
|---|:--:|---|
| `readme.txt` | **必須** | プレーンテキスト・**UTF-8（BOM なし）**。書式は下記 |
| `Dockerfile` | **必須** | コンテナの定義 |
| `compose.yaml` | **必須** | `docker compose up` で起動できる構成 |
| コード・データ | **必須** | サービス本体 |

```
app/
├── readme.txt        ← 提出直前に手元で作る（コミットしない）
├── Dockerfile
├── compose.yaml
├── src/              ← コード（英数字名で自由に切る）
└── data/             ← 使うデータ
```

### `readme.txt` に書く内容

ヘッダ（前書き）:

- Slack のチームチャンネル名（**正確に書き写す**）
- 提出者の氏名と所属（日本語で姓名、大学 / 学部・コース名）

本文（番号付き。**該当しない項目は「なし」と書く**）:

1. 概要・主要機能（**必須**。説明資料1と齟齬のないように）
2. 使用しているポート番号（ホスト OS からコンテナに接続する場合のみ）
3. ログイン情報（コンテナ接続時に必要な場合のみ）
4. 実行方法（**必須**。`docker compose up` など起動方法を正確に。説明資料1と齟齬のないように）

末尾に特記事項・補足（起動時に審査員が注意すべき事項）。

**`compose.yaml` のポート番号と `readme.txt` の記載は必ず一致させる。**

## 提出前のチェック

1. [ ] `app/` 配下に日本語ファイル名が 1 つも無い
   ```bash
   find app -name '*[^ -~]*'   # 何も出なければ OK
   ```
2. [ ] 不要ファイル・キャッシュを削除した（`__pycache__`、`.next/cache`、`.nuxt`、`node_modules` など）
3. [ ] `readme.txt` を作った（UTF-8・BOM なし・チャンネル名と氏名所属を記載）
4. [ ] **書いた本人以外の環境**で `docker compose up` して動くことを確認した
5. [ ] zip / 7z のベース名が作業ディレクトリ名になっている
   （**7z のほうが圧縮率が高く推奨**。提出前にチームを識別できる英語名へ
   ディレクトリごとリネームしてから固めると、審査員側で見分けやすい）
6. [ ] 展開し直して、作業ディレクトリが正しく展開できることを確認した

**期限（2026-09-09 17:00）に遅れた場合・提出物に著しい不備がある場合は採点されない。**
