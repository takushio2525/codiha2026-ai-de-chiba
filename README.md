# 愛で千葉は救えるのか — CODIHA 2026

**ちばオープンデータアイデアソン・ハッカソン（CODIHA）2026** ハッカソン部門・
チーム「**愛で千葉は救えるのか**」の開発リポジトリ。

千葉県や市町村などの**オープンデータ**を活用し、地域の課題解決に繋がるアイデアを
考え、その解決方法を具体的なサービスとして実装する。

作っているサービスは **CHIZUBA**（**CHI**ba + **ZU**（地図）+ **BA**（場））。
千葉県の地図系サービスを 1 つに束ね、**住民と行政が相互に情報を投稿できる**ウェブサイト。
柱は**防災**（ハザードマップ・危険箇所報告・浸水報告・注意案内）と**観光**（景観スポット・
おすすめ投稿）の 2 つで、**対応は千葉県全域・デモデータは市川市**。
何を作るかの正本は [`docs/design/requirements.md`](docs/design/requirements.md)。

## 提出物

### 1. コード（zip / 7z）

**作業ディレクトリ丸ごと**を固める。実体は [`app/`](app/) 配下。
動かすには `cd app && docker compose up` → <http://localhost:3000>。

- zip / 7z のベース名は作業ディレクトリ名にする（**7z のほうが圧縮率が高く推奨**）
- **ファイル名に日本語を使わない**（作業ディレクトリ内すべて）
- 必須ファイル: `readme.txt`（UTF-8・BOM なし）、`Dockerfile`、`compose.yaml`、コードとデータ
- キャッシュ（`__pycache__`、`.next/cache`、`.nuxt` など）は固める前に削除する

詳細と `readme.txt` の書式は [`app/README.md`](app/README.md) を読む。

### 2. 説明資料（PDF 2 種）

| # | 資料 | 制約 |
|:-:|---|---|
| 1 | サービスの概要（スライド形式） | **5 ページ以内**。目的 / コンテナの概要図 / 実行手順と実行結果 |
| 2 | 必要機能の一覧と実装の対応表 | 表形式。未実装の機能も**割愛せず「未実装」と書く** |

### 3. プレゼン資料（9/16）

PowerPoint・16:9・発表 10 分以内 + 質疑 3 分程度。**メンバーで役割分担して発表する。**
**データの参照元（クレジット）を必ず記載する。**

## 実装の前提

- プログラムは **Docker 環境**で動かす（審査員が `docker compose` で動作確認する）
- **完結したスマホ / PC アプリそのものは求められていない。** 主要なデータ処理だけでもよい。
  GUI をどこまで実装するかはよく検討し、GUI の工夫は Moqups のデザインで伝える
- 言語は任意だが Docker で実績の多いもの（Python / Node.js / Java / Go など）。コンテナは Linux
- ベースイメージは可能な限り **Docker 公式イメージ（DOI）** を使う
- 各自 **Docker アカウント**が必要（Docker Hub から pull するため）

├── app/            ★ 提出するサービス本体（CHIZUBA）。
│                     ここを丸ごと zip 化して提出する。`cd app && docker compose up` で起動
│                     （日本語ファイル名禁止・readme.txt / Dockerfile / compose.yaml を置く）

│   └── decisions/        設計判断の記録（ADR）
├── data/           ★ 取得したオープンデータと探索的分析（所見は data/analysis/findings.md）
├── assets/         オープンデータの検討用サンプル・データ形式のメモ

## 🔒 このリポジトリは public

**氏名・学籍番号・所属メール・配布資料（著作権物）・API キーを絶対にコミットしない。**
一度履歴に入ると、public では誰でも過去コミットから読めてしまう。

- 提出用 `readme.txt` には氏名と所属を書く必要があるが、**それは提出直前に手元で書く**。
  リポジトリにはコミットしない
- 配布資料の PDF そのものは置かない（要点を抽出した `課題/` の md だけを置く）
- 議事録に個人名を書かない（イニシャル等にする）

判断ルール: **氏名・学籍番号・著作権物・評価情報が 1 つでも入るなら置かない。
公開されて困るか 5 秒迷ったら置かない。**

線引き表は [`docs/before_coding.md`](docs/before_coding.md)。
push / PR のたびに CI で秘匿情報スキャンが走る
（[`.github/workflows/secret-scan.yml`](.github/workflows/secret-scan.yml)）。手元でも実行できる。

```bash
bash .github/scripts/secret_scan.sh
```
