## 共通の約束

この 4 つは全つなぎ目に効く。個別の節で繰り返さない。

1. **座標は `[経度, 緯度]` の順**（GeoJSON と MapLibre に合わせる）。
   DB のカラム（`lat` / `lon`）と Python 側だけが `緯度, 経度` の順。**行き来で間違えない**
2. **レスポンスの形は 2 通りだけ**
   - **地図が直接ソースとして読む `GET`** → **GeoJSON の `FeatureCollection` をそのまま返す**
     （MapLibre の `source.data` に URL を渡せる。変換コードが 1 段減る）
   - **それ以外すべて** → `{ ok: true, ... }` / `{ ok: false, reason: string }`
     （既存の `/api/routing` に合わせる）
3. **失敗時は HTTP ステータスも合わせる**（`400` 入力不正 / `401` 未ログイン /
   `403` 権限なし / `404` 無い / `413` 大きすぎ / `502` 外部サービス失敗 /
   `503` DB に繋がらない / `504` タイムアウト）。
   `reason` は**画面にそのまま出せる日本語**にする
4. **外部サービスを呼ぶつなぎ目には必ずタイムアウトを入れる。**
   落ちていても画面が固まらず、代わりに何が起きたか出せる形にする

## I-1: オープンデータの点（実装済み）

| 項目 | 内容 |
|---|---|
| バージョン | `v1` |
| 送る側 / 受け取る側 | `data/scripts/build_geojson.py` / `app/src/components/MapView.tsx` |
| 経路 | `app/public/data/*.geojson`（リポジトリにコミット済み。実行時に取りに行かない） |
| 頻度 | 元データを更新したときだけ手元で再生成 |

- 形式は GeoJSON の `FeatureCollection`。`geometry` は `Point`、座標は `[経度, 緯度]`
- **`properties` のキーは英字**（日本語キーにしない）。定義は**データの種類ごとに 2 つ**ある。
  施設（避難場所・AED・子育て施設）は `app/src/lib/layers.ts` の `FacilityProps`、
  景観スポット（景観100選・F-5）は `app/src/lib/scenic.ts` の `ScenicProps`
- **配列の `properties` は、MapLibre 経由では JSON 文字列に畳まれる。**
  ソースに渡した生データ（配列）とクリックイベントから受け取る値（文字列）で形が違うので、
  受け取る側で必ず均す（景観スポットは `scenicCategories()`）。
  **地図の式（`match` やフィルタ）から読む値は、はじめから文字列の別キーで持つ**
  （景観スポットの `categoryPrimary`）
- **値が空のキーは出力しない**（スクリプト側で落とす）。受け取る側は全キーを省略可能として扱う
- 市域外の座標はスクリプトが除外する

### 異常時の約束

- ファイルが取れなかったら → そのレイヤーだけ表示しない。**他のレイヤーと地図は出す**
  （景観スポットは施設レイヤーとは別に読み込むので、片方が落ちてももう片方は出る）
- `properties` に知らないキーがあったら → 無視する（ポップアップに出さない）

## I-2: 徒歩経路（実装済み）

| 項目 | 内容 |
|---|---|
| バージョン | `v1` |
| 経路 | `GET /api/routing?from=<経度>,<緯度>&to=<経度>,<緯度>`（同一オリジン） |
| 実体 | `app/src/app/api/routing/route.ts`（型定義もここが正本） |
| 中継する理由 | User-Agent の明示・1 秒 1 リクエストの制限・タイムアウト |

```jsonc
// 成功
{ "ok": true, "distanceMeters": 1234, "durationSeconds": 890, "geometry": { /* LineString */ } }
// 失敗
{ "ok": false, "reason": "経路サービスに接続できませんでした" }
```

### 異常時の約束

- OSRM が落ちている / タイムアウト → `ok: false` を返し、**画面は直線距離の概算に切り替える**
- 座標が範囲外・パースできない → `400` と `ok: false`

## I-3: 投稿の一覧取得

| 項目 | 内容 |
|---|---|
| バージョン | `v1` |
| 経路 | `GET /api/reports`（同一オリジン） |
| 頻度 | 地図を開いたとき・カテゴリを切り替えたとき・投稿した直後 |
| ログイン | **不要**（未ログインでも読める。防災情報をログインの壁の向こうに置かない） |

### クエリパラメータ

| 名前 | 型 | 必須 | 既定 | 説明 |
|---|---|:---:|---|---|
| `city` | 5 桁の数字 | — | `12203`（市川市） | 市町村コード（JIS X 0402） |
| `category` | `hazard` \| `flood` \| `spot` | — | 全部 | カンマ区切りで複数指定できる |
| `bbox` | `西,南,東,北`（度） | — | 市町村の範囲 | 地図の表示範囲。範囲外の投稿を引かないため |
| `status` | `open` \| `ack` \| `in_progress` \| `done` | — | 全部 | 対応状況で絞る |
| `from` | `YYYY-MM-DD` | — | 制限なし | **投稿日がこの日以降**（JST の暦日・その日を含む） |
| `to` | `YYYY-MM-DD` | — | 制限なし | **投稿日がこの日以前**（JST の暦日・その日の 23:59 まで含む） |
| `q` | 文字列（40 文字以内） | — | 絞らない | **タイトルと本文の部分一致**。超えたら `400` |
| `limit` | 整数 | — | `500` | 上限 `1000`。超えたら `400` |

**`q`（キーワード検索）について**

- **両側を NFKC で正規化して小文字に寄せてから**突き合わせる（`app/src/lib/searchText.ts`）。
  「ｱﾝﾀﾞｰﾊﾟｽ」と打っても「アンダーパス」に当たる。
  SQL では `lower(normalize(r.title, NFKC)) LIKE …`（`normalize` は PostgreSQL 13 以降の
  組み込み関数で、拡張は要らない）
- **LIKE のワイルドカード（`%` `_` `\`）は打ち消す。** `%` を打った人が
  意図せず「何にでも当たる」検索をしてしまわないため
- **読み（ひらがな ⇄ 漢字）までは合わせない。** 形態素解析や辞書が要るうえ、
  この規模のデータでは効果より複雑さが勝つ
- **景観スポットはこの API を通らない。** 100 件しかないので、
  読み込み済みの GeoJSON から画面側で探す（名前の日英と所在地が対象）

**`from` / `to`（浸水実績アーカイブ）について**

- 日付は **JST の暦日**で扱う。「あの雨の日どこが冠水したか」を後から引くための
  絞り込みなので、利用者が見ている日付と境目を一致させる。
  SQL では `created_at >= (from::date AT TIME ZONE 'Asia/Tokyo')` と
  `created_at < ((to::date + 1) AT TIME ZONE 'Asia/Tokyo')` になる
- 片方だけの指定でよい。**`from` と `to` が逆でもエラーにせず入れ替える**
  （日付の入力欄は順番を強制できないため）
- **形が違う値は `400`**。黙って全期間として扱わない
  （絞ったつもりで絞れていないと「この期間に投稿は無い」と読み違える）
- **注意案内（F-4）はこの絞り込みの影響を受けない。** 画面は注意案内の根拠になる
  浸水報告を**全期間で引き直す**（`MapExplorer` の `loadReports`）。
  期間を絞ったせいで「過去に浸水報告はありません」になると、防災の判断を誤らせる

### レスポンス（GeoJSON をそのまま返す）

```jsonc
{
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "geometry": { "type": "Point", "coordinates": [139.9310, 35.7218] },  // [経度, 緯度]
    "properties": {
      "id": 42,
      "category": "flood",
      "title": "○○交差点が冠水",
      "body": "膝下まで水が来ています",
      "cityCode": "12203",
      "status": "ack",
      "authorName": "たろう",        // 表示名のみ。メールアドレスは返さない
      "authorRole": "user",          // "user" | "gov"
      "createdAt": "2026-09-01T12:34:56+09:00",
      "photoCount": 1,
      "photoUrls": ["/api/photos/42/1"],
      "commentCount": 2,
      "hasOfficialComment": true,
      "details": { "rainfallMm": 18.5, "observedAt": "2026-09-01T12:30:00+09:00",
                   "amedasStation": "船橋", "depthLevel": "knee" }
    }
  }]
}
```

- **`details` はカテゴリごとに中身が変わる**（`requirements.md` §4 の表が正本）。
  受け取る側は**知らないキーを無視**する
- **メールアドレス・`provider_uid` は絶対に返さない。** 返すのは表示名とロールだけ。
  **投稿者の `id` も返さない**（誰の投稿かは表示名でしか分からない）
- **`photoUrls` の形は `/api/photos/<投稿 ID>/<通し番号>`。通し番号は 1 始まり**
  （DB の `report_photos.sort_order` は 0 始まりなので 1 ずれる）。
  写真の配信は**ログイン不要**（投稿そのものが誰でも読めるため）

### 異常時の約束

- パラメータが不正 → `400` + `{ ok: false, reason }`（この経路だけ GeoJSON ではない）
- DB に繋がらない → `503` + `{ ok: false, reason: "投稿を読み込めませんでした" }`。
  **地図と静的レイヤーは出す**（投稿レイヤーだけ空にする）
- 該当 0 件 → `200` + `features: []`（エラーにしない）

## I-4: 投稿の作成

| 項目 | 内容 |
|---|---|
| バージョン | `v1` |
| 経路 | `POST /api/reports`（`multipart/form-data`） |
| ログイン | **必須**（未ログインは `401`） |
| 1 回あたりのサイズ | 写真込みで**最大 10 MB**。超えたら `413` |

### フィールド定義

| フィールド | 型 | 必須 | 範囲・制約 | 説明 |
|---|---|:---:|---|---|
| `category` | 文字列 | ○ | `hazard` \| `flood` \| `spot` | 投稿の種類 |
| `title` | 文字列 | ○ | 1〜60 文字 | 一覧に出る見出し |
| `body` | 文字列 | ○ | 1〜1000 文字 | 本文 |
| `lat` | 数値 | ○ | 34.8〜36.2 | 緯度（千葉県の範囲） |
| `lon` | 数値 | ○ | 139.7〜140.9 | 経度（同上） |
| `photos` | ファイル | — | 0〜3 枚・各 5 MB 以内・`image/jpeg` `image/png` `image/webp` | 写真 |
| `details` | JSON 文字列 | — | 下表 | カテゴリ固有の項目 |

**`details` の中身（カテゴリ別）**

| category | キー | 型 | 説明 |
|---|---|---|---|
| `hazard` | `hazardType` | `road` \| `light` \| `bank` \| `playground` \| `other` | 危険の種別 |
| `flood` | `depthLevel` | `ankle` \| `knee` \| `waist` | 冠水の深さ（体感） |
| `flood` | `rainfallMm` `observedAt` `amedasStation` `amedasDistanceKm` | — | **クライアントから受け取らない。サーバーが I-6 と同じ取得処理を呼んで焼き込む** |
| `spot` | `spotType` | `scenery` \| `souvenir` \| `food` \| `other` | おすすめの種別（`souvenir` がお土産） |

- `city_code` は**クライアントから受け取らない**。サーバーが `lat` / `lon` を
  `municipalities.bbox` と突き合わせて決める（詐称を防ぐ）
- **`rainfallMm` も同じ理由でサーバーが決める。** F-4 の注意案内の根拠になる値なので、
  投稿者が自由に入れられてはいけない
- **`amedasDistanceKm`（観測所までの距離）を必ず一緒に保存する。**
  市川市にはアメダスが無く、最寄りの船橋まで約 10 km ある。局地的な豪雨は数 km で
  降り方が変わるので、**「この地点の雨量」と言い切らない**ために距離を持ち回る

### レスポンス

```jsonc
{ "ok": true, "report": { /* I-3 の properties と同じ形 */ } }
{ "ok": false, "reason": "写真は 5 MB 以内にしてください" }
```

### 異常時の約束

- 未ログイン → `401`。画面はログイン画面へ誘導する
- 検証に失敗 → `400`（または `413`）。**どの項目が悪いか分かる `reason`** を返す
- **写真の保存に成功して DB の INSERT に失敗したら、保存した写真を消す**
  （孤児ファイルを残さない）
- **I-6（気象）の取得に失敗しても投稿は成功させる。**
  `details.rainfallMm` を省略し、画面には「雨量を取得できませんでした」と出す。
  **雨量が取れないことを理由に浸水報告を弾かない**（現場で投稿できないほうが害が大きい）

## I-5: 投稿の更新とコメント

| 経路 | 誰が | 何を |
|---|---|---|
| `GET /api/reports/:id` | **誰でも**（ログイン不要） | 投稿 1 件 + コメント（詳細パネル S-3 が使う） |
| `PATCH /api/reports/:id` | **投稿者本人**（`title` `body` `details`）／**行政ユーザー**（`status`） | 投稿の更新 |
| `DELETE /api/reports/:id` | 投稿者本人 | 投稿の削除（写真も消す） |
| `POST /api/reports/:id/comments` | ログイン済みの全員 | コメント |

### `GET` のレスポンス

一覧（I-3）の `properties` に、**座標・コメント・投稿者かどうか**を足した形。

```jsonc
{
  "ok": true,
  "report": { /* I-3 の properties と同じ形 */ },
  "coordinates": [139.9310, 35.7218],   // [経度, 緯度]。地図をこの位置へ寄せるため
  "comments": [{
    "id": 7, "body": "現地を確認しました",
    "authorName": "市川市 道路安全課", "authorRole": "gov",
    "isOfficial": true, "createdAt": "2026-09-01T13:00:00+09:00"
  }],
  "isAuthor": false        // 今ログインしている人がこの投稿の投稿者か
}
```

- **`isAuthor` は削除ボタンを出すかの判断にだけ使う。** 投稿者の `id` を返さずに
  済ませるためにサーバーが突き合わせた結果を渡している。
  **権限判定は `DELETE` 側で改めて行う**（画面の値を信用しない）

### `PATCH` の本体

```jsonc
{ "status": "in_progress" }                       // 行政ユーザーのみ
{ "title": "…", "body": "…", "details": { … } }   // 投稿者本人のみ
```

**送った項目だけが変わる**（部分更新）。空の本体 `{}` は `400`。

| 項目 | 誰が変えられるか | 制約 |
|---|---|---|
| `status` | **担当市町村の行政ユーザーだけ**（`gov_city_code` が投稿の `city_code` と一致） | `open` / `ack` / `in_progress` / `done` |
| `title` | 投稿者本人だけ | 1〜60 文字 |
| `body` | 投稿者本人だけ | 1〜1000 文字 |
| `details` | 投稿者本人だけ | カテゴリ定義（I-4）にある**キーと選択肢だけ**を通す |

- **1 回の `PATCH` に両方の項目を混ぜてもよい**（自分の投稿を持つ行政ユーザーなど）。
  そのときは**含まれている項目ごとに権限を確かめる**ので、片方でも権限が無ければ `403`
- **`details` は丸ごと置き換えず、送られたキーだけを重ねる。**
  浸水投稿の `rainfallMm` / `observedAt` / `amedasStation` / `amedasDistanceKm` は
  **サーバーが投稿時に焼き込んだ値**（I-4）なので、投稿者が本文を直すたびに
  消えては困る。同じ理由でデモ投稿の印（`details.demo`）も残る
- **`rainfallMm` を `details` に混ぜて送っても捨てられる**（I-4 と同じ検証を通す）。
  実測で確認済み: `{"depthLevel":"knee","rainfallMm":999}` を送ると
  `depthLevel` だけが変わり、`rainfallMm` は元の値のまま
- **行政ユーザーでも他人の本文は書き換えられない。** 行政の言い分は
  `POST /comments` で公式コメントとして残す（誰が書いたか分からなくなるのを防ぐ）
- `updated_at` はサーバーが `now()` で更新する

### `PATCH` のレスポンス

```jsonc
{ "ok": true, "report": { /* I-3 の properties と同じ形 */ } }
```

更新後の姿をそのまま返す。画面はこれで手元の投稿を差し替えるので、
**読み直しのための `GET` を続けて投げなくてよい**。

### `POST /comments` の本体

```jsonc
{ "body": "現地を確認しました。今週中に補修します" }   // 1〜500 文字
```

- **`isOfficial` はクライアントから受け取らない。** サーバーが投稿者のロールを見て決める。
  ここを信用すると、一般ユーザーが行政を騙れる。
  **公式扱いにするのは「行政ユーザー」かつ「担当市町村がその投稿の市町村と一致する」ときだけ。**
  一致しない行政ユーザーもコメントはできる（誰でもできる操作なので）が、公式にはならない
- **行政ユーザーが操作できるのは `gov_city_code` と一致する投稿だけ。**
  違えば `403`（市川市の職員が船橋市の投稿を閉じられてはいけない）

### 異常時の約束

- 未ログイン → `401`（`GET` を除く。閲覧にログインは要らない）
- 権限がない → `403` + `{ ok: false, reason: "この投稿を変更する権限がありません" }`
- 投稿が無い / 削除済み → `404`
- `status` に定義外の値 → `400`

## I-6: 気象データ（雨量・雨予報）

| 項目 | 内容 |
|---|---|
| バージョン | `v1`（**実装済み**・`feat/p4-flood-weather`） |
| 経路 | `GET /api/weather?city=<市町村コード>`（同一オリジン） |
| 実体 | 気象庁 防災情報 JSON（アメダス実況・府県予報）。**認証キー不要** |
| 中継する理由 | User-Agent の明示・**サーバー側キャッシュ**・タイムアウト |
| キャッシュ | アメダス実況 **10 分**・府県予報 **30 分**・観測所表と予報区の対応 **24 時間** |

```jsonc
{
  "ok": true,
  "observation": { "rainfallMm": 18.5, "observedAt": "2026-09-01T12:30:00+09:00",
                   "station": "船橋", "distanceKm": 10.2 },  // 最寄りのアメダス
  "forecast":    { "rainExpected": true, "within": "24h",
                   "summary": "雨　所により雷を伴い激しく降る",
                   "maxPop": 60, "area": "北西部",
                   "publishedAt": "2026-09-01T11:00:00+09:00" }
}
{ "ok": false, "reason": "気象情報を取得できませんでした。" }
```

### 上流の気象庁 JSON（すべて `https://www.jma.go.jp/bosai/` 配下・キー不要）

| 用途 | パス | 取り方 |
|---|---|---|
| 観測所の一覧 | `amedas/const/amedastable.json` | 24 時間キャッシュ。**`lat`/`lon` は `[度, 分]`** |
| 最新の観測時刻 | `amedas/data/latest_time.txt` | 10 分キャッシュ。`2026-08-24T18:30:00+09:00` |
| 全国の実況 | `amedas/data/map/<YYYYMMDDhhmmss>.json` | 同上。値は **`[数値, 品質フラグ]`** |
| 市区町村 → 予報区 | `common/const/area.json` | 24 時間キャッシュ。`class20s` が全国の市区町村 |
| 府県天気予報 | `forecast/data/forecast/<府県>.json` | 30 分キャッシュ |

- 市町村コード（5 桁）→ `class20s` の 7 桁（`+ "00"`）→ `class15s` → `class10s`（予報区）→
  `offices`（発表元）と辿る。**この対応表は全国分あるので、千葉県 54 市町村すべてに効く**
- 1 時間降水量は `precipitation1h`。**品質フラグが 0 でない値は使わない**（欠測・資料不足）

### `rainExpected` の決め方

**今後 24 時間の降水確率（`pops`）の最大値が 30% 以上**なら `rainExpected: true`。

- 30% を境にしたのは、傘を持つかどうかの一般的な目安がここだから。
  これより上げると雨でも注意が出ない回が増え、下げるとほぼ毎日注意が出て意味が薄れる
- **この値は注意案内を出すかどうかの足切りにすぎない。** 画面には気象庁の降水確率
  （`maxPop`）と天気の文（`summary`）をそのまま出し、CHIZUBA が確率を作り直すことはしない
- **予報区は市町村単位では取れない。** 千葉県は「北西部 / 北東部 / 南部」の 3 区分が最小。
  だから `area` を返し、画面に予報区名を必ず出す（市町村ごとの予報だと誤解させない）

### 異常時の約束

- 気象庁が落ちている / タイムアウト（**5 秒**）→ 取れなかった側を `null` にする。
  **実況も予報も取れないときだけ `ok: false`（503）**
- **I-4 は投稿を成功させる**（雨量なしで記録する）。
  **`forecast` が取れなければ F-4 の注意案内は出さない**
  （予報が取れないのに「注意」を出すと、根拠のない警告になる）
- 最寄りのアメダスが**20 km 以上離れている**場合は `observation` を `null` にする
  （その地点の雨量として使うには遠すぎる）
- **失敗はキャッシュしない。** 気象庁が一時的に落ちたあと、TTL のあいだ復旧を
  見に行けなくなるのを防ぐ
- **投稿に焼き込む雨量はこの経路を通らない。** `POST /api/reports` が同じ取得処理
  （`app/src/lib/jma.ts`）を直接呼ぶ。自分自身へ HTTP を投げると、コンテナ内の
  自ホスト判定に引きずられて壊れやすいため。値の出どころは同じ

## I-7: `web` → `db`（データベース・実装済み）

| 項目 | 内容 |
|---|---|
| バージョン | `v1` |
| 経路 | コンテナ間ネットワーク。接続先は環境変数 `DATABASE_URL` |
| クライアント | **`pg`（node-postgres）**。ORM・マイグレーションツールは入れない |
| スキーマの投入 | `app/db/init/*.sql` を `/docker-entrypoint-initdb.d` にマウント |
| 待ち合わせ | `depends_on: condition: service_healthy` + `pg_isready` の `healthcheck` |

テーブルの一覧と役割は [`requirements.md`](requirements.md) §5。ここには**約束**だけ書く。

- **位置は `lat` / `lon` の `double precision`。** 両方にインデックスを張り、
  範囲検索（`bbox`）で使う。**PostGIS は使わない**（理由は `architecture.md` の設計判断）
- **`details` は `jsonb`。** 検索条件には使わない。使いたくなったらその項目を列に昇格させる
- **時刻は `timestamptz`。** アプリ側は JST で表示する
- 削除は**物理削除**（論理削除フラグを持たない。テーブルと分岐が増えるため）
- **既知の制約**: `/docker-entrypoint-initdb.d` はボリュームが空のときだけ走る。
  スキーマを変えたら `docker compose down -v` で作り直す

### 異常時の約束

- 接続できない → API は `503` を返す。**地図と静的レイヤーは出す**（`architecture.md` 参照）
- `web` が `db` より先に起動しようとする → `healthcheck` で待つので起きない。
  それでも失敗したら `web` を再起動する（`restart: unless-stopped` は付けない。
  審査員がログでエラーに気づけなくなるため）

## I-8: セッション（ログイン状態・実装済み）

| 項目 | 内容 |
|---|---|
| バージョン | `v1` |
| 経路 | Auth.js（NextAuth）の **JWT セッション**。DB セッションは持たない |
| 送る側 / 受け取る側 | サーバー（`app/src/lib/auth.ts`）/ 画面と API |

```jsonc
// 画面が受け取るもの
{
  "authMode": "demo",              // "google" | "demo" ← サーバーが起動時に 1 回決める
                                   //   "demo"   … デモログインだけが使える
                                   //   "google" … Google **と** デモの両方が使える（排他ではない）
  "user": { "id": 7, "displayName": "たろう",
            "role": "gov", "govCityCode": "12203" }   // 未ログインなら null
}
```

- **`authMode` はサーバーが決めて画面に渡す。** クライアント側でキーの有無を判定しない
- **`authMode` は「どちらか一方」ではない。** `"google"` は Google *も* 使えるという意味で、
  **デモログインはどちらの値でも必ず使える**（requirements.md §8-2）。
  サーバー側の分岐は誤読を避けるため `GOOGLE_LOGIN_ENABLED` を読む
- **`role` を信じてよいのはサーバーだけ。** 画面の `role` は表示の出し分けにしか使わない。
  **権限判定は必ず API 側でセッションを見て行う**（I-5 の `403`）
- メールアドレス・`provider_uid` は画面に渡さない
- **リダイレクト先（ログイン後・ログアウト後・Google のコールバック）は
  リクエストのヘッダーから決める。** ホストは `X-Forwarded-Host` →（無ければ）
  `Host`、プロトコルは `X-Forwarded-Proto` →（無ければ）`http`。
  `X-Forwarded-Port` は**見ない**（Next.js がコンテナ内の 3000 を無条件に入れるため）。
  だから公開ポートを変えても HTTPS のリバースプロキシ越しでも設定は要らない
  （`app/src/lib/publicOrigin.ts`・`requirements.md` §8-7）。
  `AUTH_URL` を設定した環境ではその固定値が優先される

### デモログインの入力（`POST /api/auth/callback/demo`）

| 項目 | 必須 | 内容 |
|---|:---:|---|
| `displayName` | ○ | 表示名（30 文字以内） |
| `role` | ○ | `"user"` または `"gov"`。**`"gov"` 以外はすべて `"user"` として扱う** |
| `govPin` | △ | 行政ロールの PIN。**`GOV_DEMO_PIN` が設定された環境で `role="gov"` のときだけ要る**（requirements.md §8-3） |

- **PIN が要るかどうかは真偽値だけを画面に渡す。** PIN 本体はサーバーから出さない
- 検証は**サーバーアクションと `authorize` の 2 箇所**。
  この経路へ直接 POST しても `authorize` が弾く

### 異常時の約束

- `AUTH_SECRET` が未設定 → **インストール ID から署名鍵を導く**（requirements.md §8-6）。
  ID すら読めないときはセッションを通さず、**警告をログに出す**（止めない）
- セッションが期限切れ → `401`。画面はログイン画面へ誘導し、**入力中の投稿内容を捨てない**
- `govPin` が違う・空 → **ログインさせない**。画面には日本語の理由を返す。
  連続 10 回失敗すると 60 秒は即座に断る（総当たり対策）

- タイルサーバーが落ちている → 背景地図と点は出す。ハザードの重ねだけ消える

## I-10: 投稿の書き出し（オープンデータ）

| 項目 | 内容 |
|---|---|
| バージョン | `v1` |
| 経路 | `GET /api/reports/export?format=csv\|geojson`（同一オリジン） |
| ログイン | **不要**（出すのは誰でも画面で読める情報だけ） |
| 使う場面 | 投稿一覧（S-5）と地図の操作パネルの「オープンデータとして持ち帰る」 |

**行政が出したデータを住民が使うだけの一方通行にせず、住民が寄せた情報も
同じように使える形にして返す**ための経路。CHIZUBA が普通の投稿サイトと
違うのはこの一往復なので、`/about` の先頭でも説明する。

### クエリパラメータ

**`format` 以外は I-3（一覧）と同じ**ものをそのまま受け取る
（`city` / `category` / `status` / `bbox` / `from` / `to` / `q` / `limit`）。
画面で絞ってから書き出すと、見えているものと同じ範囲が落ちてくる。

| 名前 | 型 | 必須 | 既定 | 説明 |
|---|---|:---:|---|---|
| `format` | `csv` \| `geojson` | — | `csv` | 書き出す形式。ほかの値は `400` |
| `limit` | 整数 | — | **`1000`** | 持ち帰る経路なので、画面用の `500` ではなく上限を既定にする |

### 出す項目

| 出す | 出さない |
|---|---|
| `id` / カテゴリ / タイトル / 本文 / 緯度経度 / 市町村コード / 対応状況 / 投稿者の**表示名**とロール / 投稿日時 / 写真の枚数 / コメント数 / 行政の回答の有無 / カテゴリ固有の項目 / 雨量（**実測のものだけ**） / デモかどうか | **ユーザー ID・メールアドレス・`provider_uid`・写真の実体**（I-3 と同じ線） |

- **デモ投稿は `is_demo`（GeoJSON では `isDemo`）で見分けられる。**
  さらに**デモ投稿の雨量は書き出さない**。あれは数字を置いてあるだけのダミーで
  観測値ではなく（`requirements.md` §7-5 の 3）、観測値の顔をした列に入れると
  受け取った人には見分けが付かないため
- **該当 0 件でもエラーにしない。** 見出しだけの CSV / 空の `FeatureCollection` を返す

### CSV

- **UTF-8 の BOM 付き・CRLF・RFC 4180。** Excel が既定の設定で開いても日本語が化けない
- 列は `id, category, category_label, title, body, latitude, longitude, city_code,
  status, status_label, author_name, author_role, author_role_label, created_at,
  photo_count, comment_count, has_official_comment, hazard_type, depth_level, spot_type,
  rainfall_mm, rainfall_station, rainfall_observed_at, is_demo` の 24 列。
  **カテゴリ固有の列は `REPORT_CATEGORIES` から作る**ので、
  カテゴリを 1 つ足せば列も自動で増える
- **利用者が書いた文字列が `=` `+` `-` `@` で始まるときは先頭に `'` を足す。**
  表計算ソフトがセルを数式として解釈するのを止めるため（中身は変えない）。
  自前で作っている数値・列挙の値はこの処理を通さない

### GeoJSON

- **RFC 7946。** 座標は `[経度, 緯度]` の WGS84、`crs` メンバーは付けない、
  小数 6 桁（≒ 0.1 m）に丸める
- 先頭に `name` / `attribution` / `note` / `generated` / `bbox` を置く。
  前 4 つは RFC 7946 §6-1 が認めている外部メンバーで、読み飛ばしても妥当な GeoJSON
- `properties` のキーは **camelCase**（I-3 の `properties` と揃える）

### 異常時の約束

- `format` が定義外 → `400`
- そのほかのパラメータの不正 → I-3 と同じ（`400` + 日本語の `reason`）
- DB に繋がらない → `503` + `{ ok: false, reason: "投稿を書き出せませんでした。" }`
