# 05. 困ったとき

**症状から引く。** 原因と、その場でできることを書いた。

---

## 5-1. 地図が出ない・色が付いていない

### 灰色（`#eeece5`）の下地だけで、道路も地名も出ない

**背景地図のタイルが取れていない。**

| 確かめること | どうする |
|---|---|
| インターネットにつながっているか | つなぐ。CHIZUBA は背景地図を国土地理院から取る |
| 会社や学校のネットワークか | 外部への通信が制限されていることがある。別の回線で試す |

**点と経路は下地の上にそのまま出る**ので、施設の場所は読める。

### ハザードの色が出ない

| 確かめること | どうする |
|---|---|
| そのトグルが ON か | 操作パネルの「ハザードマップ（浸水想定）」で ON にする |
| 不透明度が 0 に近くないか | スライダーを右へ |
| **地図を引きすぎていないか** | **ズーム 6 未満では描画しない。** 拡大する（千葉県内が見える程度なら出る） |
| **そもそも想定区域が無い場所ではないか** | **色が付いていない＝安全ではない。** 想定区域が公表されていない河川・地域がある |

### 点（施設・投稿）が 1 つも出ない

| 症状 | 原因 | どうする |
|---|---|---|
| 「オープンデータを読み込んでいます…」のまま | 読み込み中 | 数秒待つ |
| 「オープンデータの読み込みに失敗しました。ページを再読み込みしてください。」 | 同梱データの取得に失敗 | ページを再読み込み |
| 背景地図は出るのに点だけ出ない | **地図ライブラリの補助ファイルが配置されていない**（開発者向け） | `cd app && npm run build`（`prebuild` が自動で配置する）をやり直す。詳細は [仕様書 07 章](../spec/07-map.md#7-3-worker-の罠) |
| 検索欄に文字が入っている | **当たったものだけが残る仕様** | 検索欄の × を押す |
| トグルが OFF になっている | 表示を切っている | 操作パネルで ON にする |
| 期間で絞っている | | 「解除」を押す |

## 5-2. 現在地が取れない

### 「位置情報の利用が許可されませんでした。」と出る

ブラウザが位置情報をブロックしている。

| ブラウザ | 直し方 |
|---|---|
| Chrome / Edge | アドレスバー左の鍵（またはⓘ）→「位置情報」→ 許可 |
| Safari（Mac） | Safari メニュー →「設定」→「Web サイト」→「位置情報」 |
| iOS Safari | 設定アプリ →「Safari」→「位置情報」／端末の「プライバシー」も確認 |
| Firefox | アドレスバー左の鍵 → 権限をリセット |

### 「現在地を取得できませんでした。」と出る

| 原因 | どうする |
|---|---|
| **`http://` で開いている**（`localhost` を除く） | **ブラウザの仕様で、位置情報は `localhost` か HTTPS でしか使えない。** `http://localhost:3000` で開き直す |
| 屋内で GPS が届かない | 窓際へ移動するか、地図で指定する |
| 端末の位置情報サービスが切れている | 端末の設定で入れる |

### 取れなくても困らない

**「地図をクリックして出発地点を指定してください」に自動で切り替わる。**
地図の任意の場所を押せば、そこが出発地点になる。

投稿するときは**もともと地図で場所を指定する**ので、位置情報は要らない。

### 「現在地が市川市の外にあります」と出た

デモデータが市川市のぶんしかないため、最寄りの地点が遠くなる。
操作パネルの「**出発地点を地図で指定する**」で市内から試すと分かりやすい。

## 5-3. 写真が上がらない

| エラーの文言 | 原因 | どうする |
|---|---|---|
| 「写真は 3 枚までです。」 | 4 枚目を選んだ | どれかを × で外す |
| 「『◯◯』は 5 MB を超えています。」 | 1 枚が大きすぎる | 端末側で縮小するか、別の写真にする |
| 「写真は JPEG・PNG・WebP のいずれかを選んでください。」 | 形式が違う（HEIC・GIF など） | JPEG に変換する。iPhone なら設定 →「カメラ」→「フォーマット」→「互換性優先」 |
| 「画像として読めないファイルが含まれています。」 | **拡張子だけ変えたファイル**など、中身が画像でない | 本物の画像を選ぶ |
| 「写真を含めて 10 MB 以内にしてください。」 | 3 枚の合計が大きすぎる | 枚数を減らすか小さい写真にする |

### 投稿した写真が表示されない（開発者向け）

`npm run dev` で動かしているときは、**デモ投稿の写真が出ない**。
写真を配っているのは Docker のビルドなので、手元では自分でコピーする:

```bash
cd app && mkdir -p uploads && cp db/seed-photos/*.jpg uploads/
```

## 5-4. ログインできない

| エラーの文言 | 原因 | どうする |
|---|---|---|
| 「表示名を入力してください。」 | 空のまま送信した | 表示名を入れる |
| 「表示名は 30 文字以内にしてください。」 | 長すぎる | 短くする |
| 「この環境では、行政ユーザーで入るのに PIN が必要です。」 | PIN を空のまま行政ユーザーを選んだ | 運用者に PIN を聞く |
| 「行政ユーザーの PIN が違います。」 | PIN が違う | 確かめて入れ直す |
| 「行政ユーザーの PIN を続けて間違えました。N 秒待ってから…」 | 10 回続けて間違えた | **N 秒待つ。** 一般ユーザーではその間もログインできる |
| 「**ログインできませんでした。データベースに接続できているか確認してください。**」 | データベースにつながっていない | 下記 |

### 「データベースに接続できていません」と出る

ログイン画面の上に橙色の警告が出ているとき。

```bash
cd app && docker compose ps        # 2 つとも Up になっているか
cd app && docker compose logs db   # db のログを見る
```

コンテナが起動しきる前に開いた可能性がある。**数十秒待って再読み込み**する。
初回起動はスキーマとデモデータの流し込みがあるぶん時間がかかる。

### ログインしたのに、開き直すとログアウトしている

| 原因 | 説明 |
|---|---|
| **`docker compose down -v` を実行した** | データベースを作り直すと**全員ログアウトする**（投稿と写真も消える） |
| 別のポート・別の場所の CHIZUBA を開いた | セッションは**そのデータベースに縛られている**ので通らない |
| ブラウザのプライベートウィンドウ | 閉じると Cookie が消える |

### ログイン後に別の住所へ飛ばされる

`http://localhost:3000` で開いたのに `http://0.0.0.0:3000` などに飛ぶ場合、
**古い設定が残っている**可能性がある。

`app/.env` に `AUTH_URL=` の行があれば**消す**（通常は書かなくてよい。
CHIZUBA は開いた住所から自動で判断する）。

## 5-5. 投稿できない

| エラーの文言 | 原因 | どうする |
|---|---|---|
| 「投稿するにはログインしてください。」 | ログインが切れた | ログインし直す |
| 「タイトルを入力してください。」 | 空 | 入れる |
| 「タイトルは 60 文字以内にしてください。」 | 長すぎる | 短くする |
| 「説明は 1000 文字以内にしてください。」 | 長すぎる | 短くする |
| 「投稿する場所を地図で指定してください。」 | 座標が入っていない | 「選び直す」で指定し直す |
| 「**千葉県の範囲から外れています。県内の場所を指定してください。**」 | 千葉県の外を指定した | 県内を指定する |
| 「**この場所に対応している市町村がまだ登録されていません。**」 | 市町村マスタに無い場所 | 現在はデモデータの市川市のみ登録されている。市川市内で試す |
| 「投稿を保存できませんでした。しばらくしてからもう一度お試しください。」 | データベースに一時的につながらない | 少し待ってやり直す |
| 「サーバーに接続できませんでした。通信状況を確認してください。」 | 通信が切れた | 接続を確かめる |

## 5-6. 対応状況が変えられない

| 症状 | 原因 |
|---|---|
| そもそも「行政の対応状況を更新する」が出ない | **行政ユーザーでログインしていない**、または**担当している市町村の投稿ではない** |
| 「この投稿の対応状況を変更する権限がありません。」 | 同上（画面の裏で権限を確かめている） |
| 「この投稿を変更する権限がありません。」 | 他人の投稿の**本文**を直そうとした。行政ユーザーでも他人の本文は書き換えられない |

行政としての意見は**コメント**として残す。

## 5-7. 雨量が出ない・おかしい

| 症状 | 説明 |
|---|---|
| 「投稿時の雨量: 取得できませんでした」 | 投稿の瞬間に気象庁から取れなかった。**投稿そのものは成功している** |
| 「デモ用のダミー値」と出る | **起動時から入っているデモ投稿**。気象庁の観測値ではない |
| 遠い観測所の名前が出る | **その場所の実測値ではない。** 市川市にはアメダスが無く、最寄りの船橋まで約 10 km |
| 雨が降っているのに 0.0 mm/h | 最寄りの観測所では降っていない。局地的な雨は数 km で降り方が変わる |
| 操作パネルに「いまの雨量」が出ない | 気象庁から取れていない、または**浸水を投稿できないモード**（観光マップ）にいる |

## 5-8. 注意案内が出ない／消えない

| 症状 | 説明 |
|---|---|
| 出ない | 出す条件を 3 つとも満たしていない（**予報が取れている・降水確率 30% 以上・過去の浸水報告が 1 件以上**） |
| 期間で絞ったのに消えない | **仕様。** 絞ったせいで「浸水報告はありません」になると防災の判断を誤らせるため、根拠は全期間で数える |
| 浸水のトグルを OFF にしたら消えた | **仕様。** 地図に浸水のピンが出ていないのに注意だけ出ると食い違うため |

---

## 5-9. 徒歩ルートがおかしい

| 症状 | 説明 |
|---|---|
| 「**直線距離の概算**を表示しています」 | 経路サービスにつながらなかった。徒歩 4.8 km/h での目安 |
| 「経路サービスの応答が遅いため取得を打ち切りました。」 | 8 秒で打ち切った。少し待ってやり直す |
| 「この 2 地点をつなぐ徒歩経路が見つかりませんでした。」 | 川や海を挟むなど、歩いて行けない |
| 押してもすぐ結果が出ない | **1 秒に 1 回**しか問い合わせない決まりのため、続けて押すと待たされる |
| 「表示中のデータに地点がありません。」 | レイヤーを全部 OFF にしている。1 つ以上 ON にする |

## 5-10. 起動できない（開発者・審査員向け）

| 症状 | どうする |
|---|---|
| `port is already allocated` | 3000 番が塞がっている。`CHIZUBA_PORT=3100 docker compose up` |
| `docker: command not found` | Docker Desktop（または colima）を入れる |
| ビルドが途中で止まる | インターネット接続を確かめる（`npm ci` が依存を取りに行く） |
| コンテナは上がるが真っ白 | 数十秒待つ。初回はビルドと初期化に時間がかかる |
| データベースを作り直したい | `cd app && docker compose down -v && docker compose up`（**投稿・写真・ログイン状態が全部消える**） |
| デモ投稿を消したい | `app/db/init/003_seed_demo_reports.sql` を消してから `down -v` → `up` |

### 状態を確かめるコマンド

```bash
cd app
docker compose ps                                     # コンテナが 2 つとも Up か
docker compose logs -f web                            # アプリのログ
docker compose exec db psql -U chizuba -d chizuba \
  -c "SELECT count(*) FROM reports;"                  # 投稿の件数（初期状態は 22）
docker compose exec web ls -1 /app/uploads | wc -l     # 写真の枚数（初期状態は 17）
```

## 5-11. それでも直らないとき

1. **ページを再読み込み**する
2. **ブラウザを変えて**みる（Chrome / Safari / Firefox）
3. `docker compose down && docker compose up` で立て直す
4. それでも駄目なら `docker compose down -v && docker compose up`
   （**投稿・写真・ログイン状態が消える**）

仕組みの側から調べたいときは [仕様書 13 章「既知の制約」](../spec/13-limitations.md)を見る。
