# 13. 既知の制約・未実装・技術的負債

**過少申告も過大申告もしない。** 聞かれる前に自分から言えるようにしておく。
一次資料は `app/README.md`「既知の制約」と `.agent/progress.md`。

---

## 13-1. 外部サービスに依存すること

| 制約 | 詳細 | 起きること |
|---|---|---|
| **インターネット接続が要る** | 背景地図・ハザード・徒歩経路・気象は外部サービス | オフラインだと地図が下地色になる。**同梱 GeoJSON の点と投稿は出る** |
| **気象庁が落ちると雨量が取れない** | 5 秒でタイムアウト | 浸水報告は**投稿できる**（雨量が空欄になるだけ）。注意案内（F-4）は出ない |
| **OSRM が落ちると経路が概算になる** | 直線距離 ÷ 4.8 km/h | 「概算」と画面に出る。**無反応で止まることはない** |
| **OSRM は 1 秒 1 リクエスト** | 利用規約に合わせてサーバー側で制限 | 連続で押すと少し待たされる |

## 13-2. データの制約

| 制約 | 詳細 |
|---|---|
| **雨量は「最寄りのアメダスの値」** | 市川市にはアメダスが無く、最寄りの船橋まで **10.2 km**。局地的な豪雨は数 km で降り方が変わる。だから画面には**観測所名と距離を必ず添える**。20 km 以上離れていれば雨量を出さない |
| **雨の予報は市町村単位で出ない** | 気象庁の府県天気予報は千葉県を「北西部 / 北東部 / 南部」の 3 区分でしか出さない。注意案内には**予報区名を併記**する |
| **過去の実測雨量は取れない** | 気象庁のアメダス実況は直近ぶんしか配信されない。だからデモ投稿の雨量は**ダミー値**で、観測値の顔をさせない |
| **ハザードは「色が付いていない＝安全」ではない** | 想定区域が公表されていない河川・地域があり、そこはタイルが配信されていない（404）。凡例に注意書きを常時出す |
| **ハザードタイルの配信はズーム 2〜17** | それより拡大すると 17 のタイルを引き伸ばす（新しい情報は増えない）。ズーム 6 未満では描画しない |
| **町丁字の境界ポリゴンが無い** | 市川市オープンデータに無いので、面ではなく**点**で表示している |
| **景観100選の画像列が使えない** | CSV の `画像` 列は `ATTACH/...` の相対パスで、市サイトの想定される 3 通りの URL すべてで 404 を実測。写真はコモンズから別途集めた |
| **景観スポットの写真は 100 か所中 54 か所** | 残り 46 か所はコモンズに適切な写真が見つからなかった（同名別所を除外した結果） |
| **元データに誤りが 1 件ある** | AED の 1 件が経度 `129.925207`（市川市から西へ約 903 km）。**推測で直さず落としている** |
| **デモデータは市川市のみ** | 千葉県全域に対応する建付けだが、`municipalities` に入っているのは 1 行だけ |

## 13-3. 機能として未実装のもの

| 未実装 | 理由・状況 |
|---|---|
| **投稿写真の Exif が消えない** | `photoStore.ts` は受け取ったバイト列をそのまま保存する。**位置情報や撮影日時が写真に残る**。`/privacy` に正直に書いてある |
| **アカウントを利用者自身で消す画面が無い** | 退会・データ削除の UI が無い。`/privacy` に明記 |
| **コメントの編集・削除ができない** | そのための API が無い（`report_comments` に UPDATE / DELETE の経路が無い） |
| **投稿の位置と写真を後から変えられない** | 意図的（位置を動かせると写真と現場が食い違う）。ただし「間違えた位置に投稿した」ときは消して投稿し直すしかない |
| **通報の通知が無い** | 行政側に「新しい投稿が来た」と知らせる仕組みが無い。行政は自分で一覧を見に行く |
| **投稿の並べ替え・ページ送りが無い** | 新着順の 500 件（書き出しは 1000 件）で打ち切り。それ以上は取れない |
| **市町村の切り替え UI が無い** | `?city=` で URL から指定はできるが、画面に選択肢が無い。マスタに 1 行しか無いため |
| **多言語対応は景観スポットの解説だけ** | UI 自体は日本語のみ |
| **ADR（設計判断記録）が 0 件** | `docs/decisions/0001-template.md` の雛形だけ。判断の経緯は PR 本文と `.agent/` に散っている |
| **担当表が空欄** | `docs/design/assignments.md` が未記入 |

## 13-4. 性能・規模の制約（**未測定のものは未測定と書く**）

| 項目 | 状況 |
|---|---|
| **同時アクセス数の上限** | **未測定。** 負荷試験をしていない。分かっているのは「DB の接続プールが 10」「Node.js は単一プロセス」「web コンテナは 1 個」だけ |
| **投稿件数の上限** | **未測定。** 一覧は 500 件（書き出し 1000 件）で打ち切るので、それ以上の件数での挙動は確かめていない |
| **キーワード検索に索引が効かない** | `lower(normalize(title, NFKC)) LIKE '%…%'` は前方一致でなく関数も通すので、B-tree では使えない。式インデックスも `pg_trgm` も入れていない。**デモ 22 件では体感差が無い**が、数万件規模では遅くなる |
| **写真の総容量に上限が無い** | `uploads` ボリュームが埋まるまで受け付ける。容量監視も自動削除も無い |
| **投稿写真をリサイズしない** | 5 MB の写真は 5 MB のまま保存・配信する（`Cache-Control: max-age=86400` は効く） |
| **地図の点は 915 個**（123+304+388+100） | MapLibre の circle レイヤーなので実用上問題ないが、クラスタリングはしていない |

## 13-5. 運用の制約

| 制約 | 詳細 |
|---|---|
| **スキーマを変えたら `docker compose down -v`** | `db/init/*.sql` はボリュームが空のときだけ流れる。**`-v` は投稿写真も全員のログイン状態も消す** |
| **`docker compose down -v` は全員ログアウト** | インストール ID が変わるため（[06 章](06-auth.md)） |
| **web コンテナは 1 個前提** | `AUTH_SECRET` を設定すれば複数でも動くが、**キャッシュ（気象庁の JSON・インストール ID）はプロセスごと**なので、台数分だけ外部へ取りに行く |
| **`GOV_DEMO_PIN` の総当たり対策はプロセス内カウンタ** | 複数プロセスだと各プロセスで別々に数える |
| **行政ロールの妨害はできる** | PIN を 10 回わざと間違えると 60 秒はロックされる。一般ユーザーのログインと閲覧・投稿は止まらないので、公開デモとしては許容 |
| **compose のプロジェクト名が固定** | `ichikawa-opendata-map`。同じマシンで並行して `docker compose` を叩くと**互いのコンテナを作り直す**。並行させるときは `-p` で分ける |
| **プロダクト名と compose の名前が食い違う** | 名前を変えると起動中のコンテナが別プロジェクト扱いになり作り直しになるため、意図的に据え置き。起動や採点には影響しない |
| **Google OAuth アプリは testing のまま** | 本番公開するには `/privacy` の URL を Console に入れる必要がある |
| **現在地は `localhost` か HTTPS でのみ動く** | ブラウザの仕様。取れない場合は「地図をクリックして出発地点を指定」に自動で切り替わる |

## 13-6. セキュリティ上の割り切り

**「何を守っていて、何を守っていないか」を明確にしておく。**

### 守っているもの

| 対象 | 対策 |
|---|---|
| 権限の詐称 | 権限判定は必ず API 側でセッションを見て行う。画面の `role` は表示の出し分けだけ |
| 市町村をまたぐ操作 | `govCityCode === 投稿の cityCode` を毎回確認 |
| `city_code` の詐称 | クライアントから受け取らず、座標から決める |
| `isOfficial` の詐称 | クライアントから受け取らず、サーバーがロールから決める |
| `rainfallMm`・`demo` の詐称 | `details` はカテゴリ定義にあるキーしか通さない |
| 画像でないファイルの投稿 | **先頭バイトで形式を判定**（申告 MIME を信じない） |
| ディレクトリ・トラバーサル | `photoStore.ts` の `safeName()` が `path.basename` で `uploads/` に閉じ込める |
| SQL インジェクション | すべてプレースホルダ（`$1`, `$2`…）。文字列連結で SQL を組まない |
| CSV インジェクション | 利用者が書いた文字列が `=` `+` `-` `@` で始まるとき先頭に `'` を足す |
| XSS | React が既定でエスケープする。ポップアップは `textContent`（`innerHTML` を使わない） |
| 別インストールのトークン | JWT に `inst` を焼き込んで毎回突き合わせる |
| PIN の総当たり | 指数バックオフ（最大 8 秒）＋ 連続 10 回で 60 秒ロック。比較は `timingSafeEqual` |
| 秘匿情報の混入 | CI（`secret_scan.sh`） |

### 守っていないもの（割り切り）

| 対象 | 状況 |
|---|---|
| **投稿の内容の検閲** | 誰でも自由に投稿できる。不適切な投稿を止める仕組み（通報・モデレーション）が無い |
| **レート制限（投稿・コメント）** | 1 人がいくらでも連投できる。制限していない |
| **`x-forwarded-host` の偽装** | `trustHost: true` で動く前提。偽装で起きるのは「偽装した本人が別の住所へ飛ぶ」ことで、他人のセッションは取れない |
| **CSRF トークン** | Auth.js が `/api/auth/*` については処理する。投稿系 API は Cookie が `SameSite=Lax` であることに依存 |
| **HTTPS の強制** | アプリ側では強制しない。公開時は Funnel が TLS を終端する |
| **DB のパスワード** | `chizuba_local_only` を公開値にしてある（`db` はホストにポートを公開していないので、コンテナの外からは接続できない） |
| **監査ログ** | 誰がいつ何を変えたかの記録が無い（`updated_at` だけ） |

## 13-7. 技術的負債

**「今のままでも動くが、次に手を入れる人が困るもの。」**

| 負債 | なぜ困るか | 直すなら |
|---|---|---|
| **自動テストが 0 本** | 回帰に気づけない | まず `lib/` の純粋関数（`reportRange`・`searchText`・`reportExport`・`weather`）から |
| **`MapView.tsx` が 932 行** | 地図の生成・ポップアップの DOM 組み立て・9 つの `useEffect` が 1 ファイル | ポップアップの組み立てを別ファイルへ |
| **`MapExplorer.tsx` が 687 行・状態が 20 個以上** | どの状態がどれに影響するか追いにくい | `useReducer` か、地図／投稿／気象で分割 |
| **行政の色（`#0072b2`）を 2 か所に書いている** | 片方だけ変えると地図とバッジで食い違う | Tailwind v4 の任意値の制約なので、コメントで縛る以外に手が無い（**現状はこれが最善**） |
| **`docs/decisions/` が空** | 判断の経緯が PR 本文と `.agent/` に散る | 大きな判断（DB 採用・投稿モデル統一・公開 URL）を ADR に起こす |
| **`docs/design/assignments.md` が空欄** | 誰が何を持っているか分からない | 埋める |
| **`tools/example_analysis/`・`example_benchmark/`** | テンプレート由来の空の雛形が残っている | 使わないなら消す |
| **エラーのログが `console.error` / `console.warn` だけ** | 本番で何が起きたか追いにくい | 構造化ログを入れる |
| **`app/README.md` が 417 行** | 審査員向け・開発者向け・提出手順が 1 ファイルに同居 | 分割（別の担当者が作業中） |

## 13-9. 「これは制約ではない」もの（誤解されやすい点）

| 誤解 | 実際 |
|---|---|
| 「デモモードだから機能が制限されている」 | **していない。** デモログインでも投稿・コメント・行政操作まで全機能が使える |
| 「PostGIS が無いから空間検索ができない」 | 矩形検索（bbox）と距離計算はできている。使っていないのは面の重なり判定など |
| 「compose の名前が `ichikawa-opendata-map` なのは直し忘れ」 | **意図的**（[13-5](#13-5-運用の制約)） |
| 「テストが無いのはサボり」 | 期間の配分の判断。**手動での動作確認に時間を充てた**（[12 章](12-quality.md)） |
| 「注意案内が予測をしている」 | **していない。** 事実 2 つを並べているだけ（[11 章 11-6](11-decisions.md#11-6-なぜ予測と言わないか気象業務法)） |
| 「雨量はその場所の実測値」 | **違う。** 最寄りのアメダスの値。観測所名と距離を必ず併記している |
