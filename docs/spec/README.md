# CHIZUBA 仕組みと構成の仕様書

このディレクトリは、**CHIZUBA のコードを読まずに「どこに何があって、どういう仕組みで、
どこと繋がっているか」を説明できるようになる**ための文書。

想定読者は**コードを書いていない人**（発表者・審査員からの質問に答える人）。
専門用語は初出で 1 行説明を付ける。すべての記述に**ファイルパス（必要なら行番号）・SQL・
実測値・出典 URL のいずれか**を添えてある。分からなかったものは「未確認」と明記する。

- 利用者向けの操作手順は [`docs/manual/`](../manual/README.md)
- 何を作るかの正本は [`docs/design/requirements.md`](../design/requirements.md)
- つなぎ目（API の形）の正本は [`docs/design/interfaces.md`](../design/interfaces.md)
- 提出要件の正本は `課題/2026-09-09_CODIHA2026_提出要件.md`

この仕様書は**コードから起こしたもの**なので、正本と食い違ったら正本を勝たせ、
この文書を直す。

## この文書の書き方（変更するときの約束）

1. **推測を書かない。** 実際にファイルを開き、実行し、`curl` で取得した結果だけを書く。
   確かめられなかったものは「未確認」と書く
2. **「どこにある」は実パスで書く。** 行番号は変わりうるので、
   併せて関数名・定数名など grep できる手がかりを添える
3. **「どういう仕組み」には必ず「なぜその仕組みか」を付ける。**
   理由の出どころは、コードのコメント・`.agent/architecture.md`・PR 本文・git log
4. **「どこと繋がる」は双方向に書く。** 呼ぶ側の項と呼ばれる側の項の両方に書く
5. 外部資料に言及したら **URL を付け、[99 章](99-sources.md)の台帳に追記する**
