# データフォーマット仕様（記入テンプレ）

プロジェクトで扱うデータファイルの形式を決めたら、ここに書く。

> **通信のパケット形式**は [`../docs/design/interfaces.md`](../docs/design/interfaces.md) と
> [`../docs/design/protocol.md`](../docs/design/protocol.md) に書く。
> ここは「ファイルとして保存するデータ」の形式を決める場所。

## 形式の選択肢

| 形式 | 長所 | 短所 | 向いている場面 |
|---|---|---|---|
| JSON | 人間が読み書きしやすい / ツールが豊富 | サイズが大きい | 設定・階層のあるデータ |
| CSV | 表計算ソフトで編集できる / 差分が見やすい | 階層構造が表現しにくい | 計測ログ・一覧データ |
| YAML | 可読性が高い | 字下げミスに弱い / パーサ依存 | 人が手で書く設定 |
| GeoJSON | 地図に載せられる / ツールが豊富 | サイズが大きい | 位置情報を含むデータ |

**迷ったら JSON か CSV。** 自治体のオープンデータは CSV か Excel で配布されることが多いので、
**取得したままの生データと、整形後のデータは別ファイルに分ける**（整形をやり直せるようにする）。

## 変えるときのルール

**このファイルを変えるときは PR にする。** 形式が変わると、読む側のコードが全部壊れる。

- 形式を変えたら `version` を上げる
- 読む側は「知らない version が来たらエラーにする」ようにしておくと事故に気づける

## サンプル

決めた形式のサンプルを [`examples/`](examples/) に必ず 1 個置く。
これがあると、読む側は書く側の完成を待たずに実装を進められる。
