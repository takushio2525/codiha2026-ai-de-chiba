## 実装要件

- プログラミングは **Docker 環境で行う**（審査員が動作確認するため）。docker compose で起動できる構成にする
- **完結したスマホ/PC アプリそのものは求められていない**。主要なデータ処理だけでも構わない。GUI をどこまで実装するかはよく検討し、GUI の工夫は Moqups で伝える
- 言語は任意だが Docker で実績の多いもの（Python, Node.js, Java, Go など）。コンテナは Linux 環境
- ベースイメージは可能な限り Docker 公式イメージ（DOI: Docker Official Image）を使う
- Docker アカウントが必須（Docker Hub から pull するため。Google / GitHub アカウント連携でも可）

## 提出要領（0点条件 — 独立セクション・厳守）

- **期限に遅れた場合は採点されない**。提出物に著しい不備がある場合も採点されない
- 提出物は以下の3点を Slack のチーム用プライベートチャンネルに**チーム代表者が投稿**する
  - 投稿メッセージの**先頭行に太字で「資料提出」**と明記
  - zip ファイルと説明資料2種を添付
- **作業ディレクトリ丸ごとの zip（または 7z、7z の方が圧縮率が高く推奨）**
  - zip/7z のベース名は作業ディレクトリ名にする
  - **ファイル名に日本語は使わない**（作業ディレクトリ内すべて）
  - 展開後に作業ディレクトリが正しく展開できることを確認する
  - 不要ファイル・キャッシュは事前に削除（Python の `__pycache__`、Next.js の `.next/cache`、Nuxt の `.nuxt` など）
  - 必須ファイル: `readme.txt`（UTF-8・BOMなし）、`Dockerfile`、`compose.yaml`、コードやデータ
- **説明資料2種**（いずれも PDF）
  1. サービスの概要（スライド形式・**5ページ以内**）
  2. 必要機能の一覧と実装の対応表（表形式）

## readme.txt の仕様

プレーンテキスト・UTF-8（BOMなし）。

- ヘッダ（前書き）
  - Slack のチームチャンネル名（正確に書き写す）
  - 提出者の氏名と所属（日本語で姓名、大学/学部・コース名）
- 本文（番号付き。該当しない項目は「なし」と書く）
  1. 概要・主要機能（**必須**。説明資料1と齟齬のないように）
  2. 使用しているポート番号（ホストOSからコンテナに接続する場合のみ）
  3. ログイン情報（コンテナ接続時に必要な場合のみ）
  4. 実行方法（**必須**。`docker compose up` など起動方法を正確に。説明資料1と齟齬のないように）
  - 特記事項・補足（起動時に審査員が注意すべき事項など）

## 説明資料の仕様

### 1. サービスの概要（PDF・スライド・5ページ以内）

1. サービスの目的 — 何をどのように解決するかを具体的に
2. コンテナの概要 — 図でコンテナ実行時の様子を説明。コンテナを実行しながら読む前提の書き方
3. コンテナ実行の手順と実行結果 — 実行結果はスクリーンショットなどで具体的に

Moqups でデザインした GUI を活用するとよい。

### 2. 必要機能の一覧と実装の対応表（PDF・表形式）

| 番号 | 必要機能 | 対応する実装 | 備考 |
|------|----------|--------------|------|

- 必要機能はサービス概要と対応した機能を簡潔に。**行分けを適切に**（大まかすぎず細かすぎず）
- 対応する実装は「どのファイルのどこか」を記す。未実装の機能も**割愛せず**「未実装」と書く（**過少申告しない**）

## Docker 構成の参考（配布資料の作成例）

- 例1（バッチ型）: CSV を読み matplotlib で PNG 出力する Python コンテナ。`compose.yaml` の `volumes: ./data:/app/data` でホストとバインドし、結果をホスト側で確認する
- 例2（サーバ型）: Flask web + MySQL db の2コンテナ構成。`depends_on` + `healthcheck` で db 起動を待ち、`ports: "8000:5000"` でホストから `localhost:8000` にアクセス。DB は named volume で永続化
- 提出の流れ: ベースイメージ選定 → コード + Dockerfile / compose.yaml を並行作成 → コンテナ実行 → コードを書いたメンバー以外の環境でも動作確認 → 提出物準備

## 運用メモ（チーム内・AI向け補足）

- チーム連絡・メンター相談・**提出**はすべてハッカソン Slack のチーム用プライベートチャンネルで行う。提出後はメンションを見逃さない
- 生成 AI の利用は可。ただし鵜呑みにせず「自分のもの」にする（内容を理解して説明できる状態にする）
- このリポジトリは開発用。**提出用の作業ディレクトリ（zip 化対象）は日本語ファイル名禁止**なので、提出対象のアプリ本体はリポジトリ内の英語名ディレクトリに置き、その単位で zip 化できる構成にする
- 実装は「実装割合 × 動作割合」で採点される。**動かない機能を積むより、動く機能を確実に**
