# .agent — AI 向けの詳細仕様と作業文脈

## `docs/` との違い

同じような内容に見えるが、**読む相手が違う**。

| | 読む相手 | 目的 | 書き方 |
|---|---|---|---|
| `docs/` | **人間** | 設計を理解し、議論し、報告書に使う | 図・背景・経緯を含めて丁寧に |
| `.agent/` | **AI** | 作業に必要な事実を素早く拾う | 事実だけ簡潔に。飾らない |

内容が重複してもよい。**役割が違うので分けている。**

## 何のためにあるのか

AI とのやり取りは、セッションが変わると文脈がリセットされる。
毎回「このプロジェクトは何か」「前回どこまでやったか」を説明し直すのは無駄が大きい。

`.agent/` にそれを書いておくと、**別の日・別の人・別のツールでも同じ前提から始められる。**
実際、この仕組みは書いた本人が読み返すのにも役立つ（1 週間空けると自分でも忘れる）。

## ファイル

| ファイル | 内容 | いつ更新するか |
|---|---|---|
| `activeContext.md` | **今の状態**（何を触っているか・次の一手） | 作業のたびに**上書き**（履歴は残さない） |
| `progress.md` | 完了した作業の時系列 | 作業が一段落したら**追記** |
| `architecture.md` | システム構成・設計判断・データの流れ | 設計が変わったとき |
| `conventions.md` | コーディング規約・命名・ファイル配置 | 規約を決めたとき |

## 肥大化させない

**これがいちばん大事。** 放っておくと際限なく膨らみ、毎回の読み込みが重くなる。

### activeContext.md

- **「現在の状態」だけ**を書く。「今日やったこと」「前回やったこと」の節を作らない
- 過去の作業は `progress.md` へ。ここには残さない
- **80 行を超えたら太りすぎのサイン。** 過去の話を `progress.md` へ逃がす

### progress.md

- 1 エントリ **1〜3 行**。詳細は git log とコミットメッセージに任せる
- 古いエントリが増えてきたら `progress-archive.md` に移す

## AI ツールから読ませる

`AGENTS.md` の末尾で `@.agent/activeContext.md` のように参照している。
`@` を付けたファイルは**毎回全文が読み込まれる**ので、
常に必要なもの（現在状態と履歴）だけに絞る。

設計書のような重いファイルは `` `.agent/architecture.md` `` のように
バックティックで書いておき、**AI が必要なときだけ開く**ようにする。

## 使わない班は

`.agent/` ごと削除してよい（`AGENTS.md` の末尾の `@` 参照も消す）。
AI を使わない開発なら不要。
